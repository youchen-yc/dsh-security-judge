# 安全设计与威胁模型（security-judge）

## 1. 信任边界（A-01）

```
[DSH 浏览器页面] --HTTP(同源, 页面令牌)--> [Host 插件 HTTP 接口]
        |                                          |
        | 自定义头 x-security-judge-token           | core.dispatch → 仅评审状态
        v                                          v
   [Web 面板 client.js]                     [会话事件日志 session/event]
                                                   |
                                                   v
                                   [会话 AI（Agent）] ← 注入评审提醒/教学（需授权）
                                                   |
                                                   v
                                   [工作目录文件（只读，仅会话改动过的文件/包目录）]
```

- 身份转换点：浏览器页面 → Host HTTP（同源 + 页面令牌）；Host → 会话（注入的用户消息）；
  Host → 文件系统（只读 touched files 与包目录）。
- 不信任：会话里的代码文本、文件路径、会话标题、外部分发的安装包内容（都按不可信输入处理）。
- 数据流：只读，评审结果写回自己的状态文件与面板；不把任何数据发到网络。

## 2. 架构假设（A-06）

- 安全性只依赖：页面令牌（随机、每次加载）、宿主同源、用户授权状态；不依赖源码保密。
- 假设攻击者可以读到全部源码；本设计在源码公开下仍成立。
- 不假设「内网/本机」可信：面板写操作一律校验令牌。

## 3. 威胁建模（STRIDE，I-01）

| 威胁 | 场景 | 缓解 |
| --- | --- | --- |
| S 身份伪造 | 跨站页面伪造面板请求 | 页面令牌 + 同源校验 + 写操作强制令牌 |
| T 篡改 | 篡改评审结论/授权状态 | 状态只在本机 profile 目录；权限仅当前用户；无远程写入口 |
| R 抵赖 | 谁授权、谁提交评审 | store 记录 history（授权、评审、重做） |
| I 信息泄露 | 面板接口被本机其他进程读取 | 读接口只读同源；令牌不落盘、不进日志；不读与代码无关文件 |
| D 拒绝服务 | 超大请求体拖垮 Host | 请求体上限 1MB、会话扫描条数上限、面板轮询节流 |
| E 权限提升 | 未授权静默 grant-authority | 写操作必须页面令牌；令牌只注入页面；跨站预检拦截 |

## 4. 最小权限与权限分离（A-07 / A-08）

- 评审插件本身不修改代码、不修改宿主配置、不代替用户决定；只有「评审 + 注入提醒 + 回合门禁」。
- 破坏性/高影响动作（授权、撤销、豁免、强制重做、注入提醒）都需要用户授权（authority）与页面令牌双重条件。
- 插件不申请任何系统权限；HTTP 仅监听宿主已开的本地 Web 端口。

## 5. 纵深防御（A-04）

关键资产 = 「评审权限 / 授权状态」：
1. 页面令牌校验（Host）；
2. 同源 Origin 校验（Host）；
3. 用户授权状态（插件逻辑层）；
4. 令牌不落盘 + 不写日志（减少泄露面）。

## 6. 输入处理（A-05 / E 组）

- HTTP 请求：JSON 解析失败拒绝；请求体 ≤1MB；action 白名单；参数类型校验。
- 会话事件：工具参数按 JSON 解析失败即跳过；文件路径只用于定位 touched files；内容长度截断。
- 安装包自检：只读 package.json/exports/files/patch 等声明，不执行包内代码。
- 面板渲染：全部 React 文本渲染，无 innerHTML/dangerouslySetInnerHTML；无 eval/new Function。

## 7. 密码与密钥（D 组）

- 本插件无用户口令、无自有会话令牌、无网络通信、无加密存储需求；
- 唯一秘密是内存中的页面令牌：使用 `crypto.randomBytes(24)` 生成，`timingSafeEqual` 比对，不落盘、不写日志；
- 发布产物签名使用独立的 Ed25519 密钥（见 dist/release-signing.pub.pem 与 dist/*.sig）。

## 8. 日志与错误（H 组）

- 日志只记录插件运行事件（会话 id、规则编号、错误消息），不记录 token/口令/文件内容；
- HTTP 错误返回通用信息，不泄露堆栈给调用方（堆栈只进 Host 日志）。

## 9. 残余风险

- 能读取本机页面 HTML 的本机进程可拿到页面令牌；属于本机进程权限问题，插件无法隔离。
- 静态自检不替代渗透测试；规则 J 的「另一台机器安装验证」以干净目录验证记录为准。
- 插件只读本机文件与 DSH 会话；对宿主本身的安全依赖 DSH 的权限模型。
